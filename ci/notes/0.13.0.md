Try counts that follow the strategy, and a command line that uses your settings. The backtests are the same as in 0.12.0, and the counts of named strategies stay as they are.

- **A strategy needs a name to be counted.** A block with no `name:` line no longer keeps a count of tries or versions. Before, the plugin knew such a block only by its place in the note, so a block added above it took over its count, and "Was it luck?" could read the tries of another strategy. Now "Was it luck?" says that the block has no name, with a button, "Give the strategy a name". When you give a name, the block takes along the count that 0.12.0 kept for it, if that count has the block's text.
- **Moving or copying a strategy to another note.** Cut a named block from one note and paste it into another, and its result offers "Move the record to this note". Copy it, and the copy offers "Add them to the count". The tries of a sweep in the first note then still count in the second, so "Was it luck?" does not see only the run shown. Nothing changes until you press the button. A move does not change links such as `[[Scratch#Trend]]`.
- **The command line and the MCP server use your settings.** `run` and `run_backtest` read the plugin settings that the vault keeps (starting money, costs, slippage, commission, interest on cash, data source and how long prices stay fresh), so they give the result that Obsidian gives. `run` names the settings file that it read. A vault with no settings file uses the default settings.
- **Less memory.** The plugin no longer keeps a copy of the saved price files in memory (up to 60 MB). It reads them from the disk when it needs them.
